BEFORE DEPLOYING:
Back up the current live DATA_FILE, avatars and JWT_SECRET. See docs/database-setup.md.
Set DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/DATABASE in the Node hosting environment. Keep the same stable JWT_SECRET.
The MySQL server must allow connections from the Node host. A cPanel database on another server cannot use localhost as its host from Node.
Set NODE_ENV=production and keep MAIL_TRANSPORT=bridge. Keep existing MAIL_BRIDGE_URL and MAIL_BRIDGE_TOKEN.
Production now refuses startup without persistent storage and a stable JWT_SECRET.

Deploy aliasmail-speed-fix.zip to Node, preserving environment and database. Restart Node and check for '[store] using the mysql database'.
The tables app_state, app_files and app_mail_cache are created automatically. Existing populated SQL data is retained. An empty database can import existing local JSON state and avatars if still present.
Do not publish private backups or credentials in a repository, application ZIP or web directory. If the old live files have already been erased, restore from a hosting backup.
No PHP bridge update is required for this release.
Persistent message caching is enabled by default (250 MB, 30 days idle retention, messages up to 5 MB).
See docs/database-setup.md and docs/mail-performance.md.
